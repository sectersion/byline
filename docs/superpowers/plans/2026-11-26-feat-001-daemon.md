# FEAT-001: the daemon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local daemon that accepts WakaTime heartbeats, stores them raw in sqlite, forwards them upstream transparently, and answers locally (report/status/setup).

**Architecture:** One sync process. `tiny_http` listener on 127.0.0.1:8787 serving 4 endpoints; every heartbeat written to sqlite exactly as received before any network activity; a forwarding drain loop with backoff over `forwarded_at IS NULL`. Pure derivation functions for report/status. No agent stream in this plan (FEAT-002).

**Tech Stack:** Rust, rusqlite (bundled), tiny_http, serde_json. Forwarding: ureq (rustls).

**Spec:** docs/superpowers/specs/2026-11-26-architecture-design.md + docs/wakatime-contract.md (wire truth) + CLAUDE.md (budgets).

## Global Constraints

- Wire: bind `127.0.0.1` only; base path `/api/v1`; auth `Basic base64(key)` NO colon; ack 201 with `{"responses":[[<heartbeat>,201],...]}` one pair per heartbeat in order.
- Store raw payload bytes exactly as received + `received_at`; never mutate; never dedupe (Hackatime dedupes its side).
- Local write must never fail because upstream is down; retry queue is the query `forwarded_at IS NULL`, never a new table.
- No file >400 lines (warn 300); src/ <2,500; ≤1 new dep per PR (added to ALLOWED in budget_test.rs same commit); one surface per PR.
- Never store prompts/code/file contents/window titles anywhere, including logs. Unknown fields arrive in payloads — raw storage keeps them but logs must not echo bodies.
- Never cache a derived number; report/status compute from rows.
- Every task: 1 issue + 1 PR, tag FEAT-001 in all five places (issue/branch/commit/PR title/body).

## Review Focus

- **Chunked/keep-alive plugin requests** — real editors send `Transfer-Encoding: chunked` and reuse connections; expect: handled by tiny_http, no hang. Test in Task 2 (bulk with two sequential requests on one connection).
- **Empty/garbage JSON bodies** — malformed body must not crash the daemon and must not lose data: 400 + raw body to debug file, no sqlite write of a broken row. Test in Task 2.
- **Upstream down mid-batch** — some rows forwarded, connection dies: committed forwarded_at stays, unforwarded stay queued, no double forward after restart. Test in Task 3.
- **Clock skew between received_at and heartbeat time** — report groups by local day of heartbeat `time` (the user's working day), not received_at. Test in Task 5.
- **wakatime.cfg mid-flight rewrite by hackatime-setup** — setup re-run after hackatime-setup has clobbered: must detect current api_url is no longer byline's and re-claim it, printing what changed. Test in Task 4.

```sql
-- docs/schema.sql — frozen after FEAT-001 merges
CREATE TABLE heartbeats (
  id INTEGER PRIMARY KEY,
  raw TEXT NOT NULL,              -- payload object exactly as received
  received_at INTEGER NOT NULL,   -- unix seconds, byline's clock
  forwarded_at INTEGER,           -- null = queued
  auth_method TEXT NOT NULL,      -- 'basic' | 'query'
  api_key TEXT NOT NULL           -- the key it arrived with (needed to forward)
);
CREATE TABLE agent_heartbeats (
  id INTEGER PRIMARY KEY,
  raw TEXT NOT NULL,              -- composed agent heartbeat as sent upstream
  received_at INTEGER NOT NULL,
  forwarded_at INTEGER,
  hook_source TEXT NOT NULL       -- e.g. 'claude-code'
);
CREATE TABLE unknown_paths (
  id INTEGER PRIMARY KEY,
  path TEXT NOT NULL,
  method TEXT NOT NULL,
  hit_at INTEGER NOT NULL
);
CREATE TABLE config (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
CREATE TABLE sessions_cache (
  -- placeholder: FORBIDDEN to use for derived numbers; kept empty until a
  -- genuine non-derivable need appears, else dropped at next migration
  id INTEGER PRIMARY KEY
);
CREATE TABLE schema_meta (
  version INTEGER NOT NULL
);
```
