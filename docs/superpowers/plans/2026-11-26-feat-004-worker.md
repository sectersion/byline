# FEAT-004: the worker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Cloudflare worker: homepage (center-aligned, hero = live aggregate of unreviewed logged hours), docs, install script, submitted-hours storage for the review flow. On-by-default anonymous hero number, opt-out with one flag.

**Architecture:** One Worker + one D1 database. Routes: `/` homepage, `/docs` static, `/install.sh`, `POST /api/hours` (daemon's hero ping), `POST /api/submit` + `GET /e/:id` (review artifact storage). No accounts, no auth beyond a per-install daemon token, no dashboard.

**Tech Stack:** Cloudflare Workers, D1, cf CLI (`cf` preferred per user CLAUDE.md — no wrangler config in repo; use `cf` unless a project wrangler config exists).

**Spec:** docs/superpowers/specs/2026-11-26-architecture-design.md (worker scope), review-artifact.md (hero number, review flow).

## Global Constraints

- Worker budget mirrors daemon budgets (its own budget test or a size cap in CI — CHORE if it needs its own rule).
- Hero POST carries ONE number + an install id (random, generated at setup, not tied to identity). No project names, no timestamps beyond the ping's own time, no rows. D1 stores only: install_id (hashed), running total.
- Homepage center-aligned (matches repo README); the fraud-control one-liner appears there too.
- Opt-out: `byline setup --no-hero` writes config; the daemon then never POSTs. Default is ON (decided 2026-11-26).
- No user data in worker logs; D1 rows auditable by design (what you see is what's stored).

## Review Focus

- **Install-id privacy** — hashed at rest; a rotated id must split the running total into a new row rather than inflate. Test in Task 2.
- **Submission URL abuse** — `/e/:id` artifacts are public-by-default (the program's review model) but must be unguessable: id is 16+ chars random, and submission POST requires the daemon token. Test in Task 3.
- **Hero inflation by fabricated pings** — the hero is unreviewed logged hours and needs no trust (doc); but a single install must not be able to move it arbitrarily: cap per-install ping delta (e.g. +40h/day) server-side. Test in Task 2.
